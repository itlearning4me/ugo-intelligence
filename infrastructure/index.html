Ugo HA Cluster Reference

What the cluster is for

Today Ugo runs on one Raspberry Pi 5 under docker-compose, with every scheduled job in one process, so one failure takes it offline. The target is three Dell OptiPlex 7050 Micro nodes running a Proxmox cluster, one Ubuntu VM per node, and those three VMs forming one k3s cluster. The design rule behind every phase: every stateful piece (etcd, Postgres, Redis, Longhorn) keeps exactly one member per physical node. Lose any one machine and the other two keep quorum and keep serving, with about a minute of disruption and no data loss.

Architecture: how requests, data and deploys flow

Nothing is exposed to the internet directly. Requests come in through Cloudflare Tunnel, backups go out to Cloudflare R2, and images are built in GitHub Actions and pulled from GHCR. Deploys reach the cluster only through a self-hosted runner on the LAN.

Node layout: one member of everything on every node

Any two nodes form a majority, so etcd, Postgres and Redis Sentinel keep quorum with one node down. Cloudflared runs two replicas, so one node has none. With a node down, the third API and web pod stay pending until it returns; two carry the load.

01

BIOS

done · 21 Oct

Makes the three machines behave identically and boot without a keyboard or monitor.

  1. UEFI only, SATA mode AHCI.
  2. VT-x and VT-d on, for virtualisation and device passthrough.
  3. Wi-Fi and Bluetooth off.
  4. Power on after power loss, so a node returns by itself after an outage.
  5. Boots headless.
02

Proxmox VE install

done · 21 Oct

Installs Proxmox VE 9.2 on each node and fixes the Intel I219 NIC hang that would otherwise drop a node out of the cluster.

  1. Install to NVMe with ext4 + LVM-thin.
  2. Switch to the no-subscription repository; install CPU microcode.
  3. Turn NIC offloads off on the onboard Intel NIC (the hang fix).
  4. Create vmbr0 on the LAN and vmbr1 on the 2.5 GbE adapter.
  5. Enable chrony time sync, which corosync and etcd depend on.
03

Proxmox cluster

done · 26 Oct
infra/cluster/03-proxmox-cluster.shinfra/cluster/hosts/

Forms the three hosts into the cluster ugo-pve, with corosync on two links.

  1. pvecm create on pve1, pvecm add on pve2 and pve3.
  2. Confirm 3 of 3 votes and Quorate: Yes.
  3. Set link priorities: link 1 (2.5 GbE) at 20, link 0 (LAN) at 10.
  4. Test failover both ways by unplugging each link.
  5. Back up host config (interfaces, hosts, corosync.conf) to Git.
Corosync link selection
flowchart LR
    A[Corosync heartbeat] --> B{2.5 GbE link up?}
    B -->|Yes, priority 20| C[Link 1: dedicated cluster link]
    B -->|No| D[Link 0: LAN, priority 10]
    C --> E[Quorum held]
    D --> E
Found on the live cluster: corosync was first using the shared LAN. Setting link priorities fixed it with no loss of quorum. After the fix the 2.5 GbE link carries 800 packets per 10 s against 88 on the LAN.

05

k3s and kube-vip

done · 1 Nov
infra/cluster/05-bootstrap-k3s.sh

Builds an HA control plane: three k3s servers with embedded etcd behind one floating API address.

  1. Write each node's /etc/rancher/k3s/config.yaml: cluster-init on k8s-1, join on the others, zone labels pve1–pve3.
  2. Install k3s v1.36.5+k3s1 with secrets encryption on.
  3. Install kube-vip v1.3.1 on k8s-1 and confirm the VIP answers.
  4. Join k8s-2 and k8s-3 through the VIP.
  5. Schedule etcd snapshots every 6 h to R2; verify the upload.
  6. Test VIP failover from k8s-1 to k8s-3.
Bootstrap order
flowchart LR
    A[k8s-1: cluster-init] --> B[kube-vip up]
    B --> C{VIP answers?}
    C -->|Yes| D[k8s-2 joins via VIP]
    D --> E[k8s-3 joins via VIP]

Kubelet reserves 512 MiB each for Kubernetes and the system, and evicts below 300 MiB free.

07

App changes and images

in repo
api/main.pyinfra/redis_client.pyinfra/jobs.py

Makes the app safe to run as three copies.

  1. Split health checks into /healthz (liveness) and /readyz (DB + Redis).
  2. Redis client speaks Sentinel when a sentinel host is configured; local dev is unchanged.
  3. Read the real client IP from CF-Connecting-IP for rate limiting.
  4. Deduplicate Stripe and Resend webhook events in a processed_events table.
  5. Replace the APScheduler process with five CronJobs that take a Redis lock.
  6. Build non-root, multi-arch images.
Without the lock, three API replicas would run every scheduled job three times.

Migration and cutover

in repo ~30 min window
infra/migration/

Rehearse once, then cut over from the Pi in about 30 minutes, clear of the 04:00 UTC brief. Postgres is 18 on both sides, so this is a same-version dump and restore.

Workflow

Redis is not migrated; people sign in again with a magic link. CronJobs are switched on by a git commit, not kubectl patch, because CI re-applies manifests on every push.
